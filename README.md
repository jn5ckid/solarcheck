# 솔라체크 (SolarCheck)

주소와 입면 사진 1장으로 노후 건축물 외피(지붕·입면) 태양광 적용 가능성을 판정하는 웹 서비스의 해커톤 구현본.

- `prep/` 사전 계산 (Python): GIS 윤곽 → 블록·분석면 → 센서 격자 → 지평선 → 일사
- `docs/` 웹 (GitHub Pages 배포 폴더): 도로명주소 조회 → 건축물대장·주변 건물 3D → 입면별 연·월평균 일사량
- `tests/` 산정 로직 테스트
- `backend/` 연구실 PC에서 실행하는 FastAPI 주소·건물 조회 및 연결 시험 서버
- `docs/connection-test/` 주소·사진을 연구실 PC로 전송하는 연결 시험 화면

## 건물 입면에 사진 입히기

메인 화면에서 등록된 건물을 선택하고 남·동·북·서 입면 중 하나를 고릅니다.
**사진 촬영·선택**을 누르면 **사진 촬영**과 **기존 사진 선택**을 따로 고를 수 있습니다.
촬영 버튼은 휴대폰 후면 카메라를 요청합니다. 기기·브라우저에 따라 파일 선택 화면이 열릴 수 있습니다.
사진의 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래를 지정한 뒤
**이 입면에 사진 입히기**를 누르면 보정 사진이 해당 3D 벽면에만 표시됩니다.
건물을 드래그해 회전하고 휠로 확대할 수 있으며, 방향키·더하기/빼기 키도 지원합니다.
사진과 자동 판별 후 보정한 설치 영역은 건물·입면별로 이 브라우저의 IndexedDB에 저장됩니다.
새로고침 후에도 복원되지만 다른 기기와 공유되거나 연구실 PC에 저장되는 것은 아닙니다.
실제 사진은 GitHub 저장소로 업로드하지 않습니다.

메인 화면에서 실제 주소를 입력하면 연구실 PC 서버를 통해 브이월드의 건물 형상과 주변 건물을 조회합니다.
건축HUB 인증키가 있으면 사용승인일·용도·규모도 조회합니다. 설치와 사용법은 [ADDRESS_LOOKUP.md](ADDRESS_LOOKUP.md)를 참고하세요.
높이는 건축물대장 값을 우선 사용하고, 없으면 층수 × 3.3m 추정임을 표시합니다. 둘 다 없으면 3D 입면 생성을 보류합니다.
연구 대상지의 기준점은 `서울특별시 동작구 상도로47길 102`(`126.95190436549447, 37.5037278415151`)이며, 연구 로컬 `(0,0)`, X=동, Y=북으로 고정했습니다. 도로명주소를 위·경도로 변환한 뒤 공공 건물 외곽과 연구 센서 외곽을 비교합니다. 기준 건물은 `B1257`과 중심 1.26m, 외곽 중첩률 76.6%로 일치합니다.
E2c 대리모델의 원래 연구 좌표 추론은 프로젝트 Python에서 연결·검증했습니다. 주소 건물이 고정 연구 대상지 건물과 엄격하게 매칭될 때만 기존 연간 예측과 8,760시간 기반 월별 결과를 연결하며, 대상지 밖과 모호한 매칭은 차단합니다. 파일·전처리·검증 결과는 [SURROGATE_INTEGRATION.md](SURROGATE_INTEGRATION.md)를 참고하세요.
기존 연구 대상지는 sensor-disjoint 100,000점 패키지로 고정했으며, 로컬 SQLite 매핑을 생성하면 `/api/research-site` 이하의 읽기 전용 API로 건물·표면 그룹·센서별 연간 예측을 조회할 수 있습니다.
웹은 연구 대상지 내부 주소 입력을 유일한 진입점으로 사용합니다. 공공 건축물대장 정보는 유지한 채, 검증 매칭된 연구 건물의 일사량을 대상 건물 면 컬러맵과 입면별 연평균 카드로 표시합니다. 주변 건물 3D 범위는 사용자가 선택한 100/200/300m 조회 반경과 동일하게 적용하고, 지형 고저가 없는 평면 지면을 가정합니다. 대상 블록의 지붕·입면에는 1.5m 간격 분석 위치를 만들고, 매칭된 연구 건물의 Z 범위·단위 법선·8방위 차폐각으로 E2c 연간 예측을 실행합니다. 포인트 표시는 선택적으로 켤 수 있으며 화면에서만 법선 방향 0.05m 이격하고 주변 건물 표시 중에는 크기를 1/5로 줄입니다. 계산에는 원래 연구 XYZ를 그대로 사용합니다.
입면별 연평균 카드를 누르면 E2c의 8,760시간 결과를 달력 월별로 적산하고 선택 표면 전체를 평균한 12개월 차트를 표시합니다. 단위는 kWh/㎡·월이며 12개월 합계는 카드의 kWh/㎡·년 값과 대응합니다. 개별 센서·날짜 선택 UI는 제거했고, 연구 입면을 선택한 경우에는 실제 건물 입면 사진을 촬영하거나 선택할 수 있습니다.
내부 데모 자료는 개발 검증용으로만 남겨 두고 메인 화면에는 노출하지 않습니다. 격자별 시간 출력이 있는 경우 사진 편집 비율을 시간별 발전량에 적용하며, 연간 총량만으로 시간별 결과를 만들지 않습니다.
원근 보정된 입면 사진은 색상 대비·명암·경계 강도를 이용해 창문·문 후보 격자를 자동으로 제안합니다. 이 경량 판별은 확정적인 의미 분할 모델이 아니므로 사용자가 격자를 눌러 제외·절반·벽면 상태를 확인하고 보정해야 합니다.

## 연구실 PC 연결 시험

기존 사전진단 화면은 유지하고, 서버 왕복 통신 시험은 별도 화면에서 진행합니다.

- 기존 화면: https://jn5ckid.github.io/solarcheck/
- 연결 시험: https://jn5ckid.github.io/solarcheck/connection-test/
- 실행 및 외부 접속 안내: [CONNECTION_TEST.md](CONNECTION_TEST.md)

연결 시험 서버는 업로드 접수만 응답하며 실제 GIS·AI 분석은 아직 연결하지 않았습니다.
기존 화면의 사전 계산 결과와 연결 시험 서버의 응답은 서로 별개입니다.

## 실행

```bash
pip install -r requirements.txt

# 1) GIS 파일 → 사이트 입력 (데모는 prep/sites/demo_seoul.json 이 이미 있음)
python prep/gis_to_site.py raw/buildings.gpkg --lon 128.53 --lat 35.84 --site-id A_daegu \
    --height-col <높이 열> --floors-col <층수 열> --use 근린생활시설 --approval-year 1998 --gfa 6801.9

# 2) 사전 계산 → docs/data/sites/<id>/
python prep/build_site.py prep/sites/demo_seoul.json --epw <서울 EPW 경로>

# 3) 로컬 확인 (file:// 로 열면 JSON을 못 읽음)
cd docs && python -m http.server 5500      # 휴대폰은 같은 와이파이에서 http://<노트북 IP>:5500

# 4) 산정 테스트
node --test tests/calc.test.mjs

# 5) 기존 연구 대상지 패키지 검증·매핑 생성
python -m prep.audit_research_site
python -m prep.build_research_site_mapping
```

GitHub Pages: 저장소 Settings → Pages → Branch `main`, 폴더 `/docs`.
휴대폰 카메라 촬영은 HTTPS(Pages) 또는 localhost에서만 확실히 동작한다.

## 좌표 규약

대상 건물 윤곽 중심 원점, x = 동, y = 북, z = 위 (m). 방위각은 북 = 0°, 시계방향.
입면은 반시계 윤곽의 변 `p0 → p1`, 밖에서 보면 `p0`이 왼쪽. 격자 인덱스는 `t * ns + s` (t = 0이 1층 쪽).
